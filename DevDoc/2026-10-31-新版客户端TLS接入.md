## 原生服务端改动

- `Sources/MultiServer/Heaven/ClientTls.h`、`.cpp`：现有 Heaven 模块中的 TLS 上下文及每连接状态，使用 OpenSSL 内存 BIO，支持握手、加解密、分片、粘包、关闭及接收后握手消息。
- `Sources/MultiServer/Heaven/ServerStage.h`、`.cpp`：接入现有 IOCP，TLS 完成前保留 AccountBegin 及待发应用数据；握手完成后加密发送。所有 TLS 调用、输出顺序及连接清理使用现有连接管理锁。
- 公共客户端连接显式启用 TLS。Bishop 的内部游戏服监听、Goddess、支付及转发等内部连接继续使用原传输方式。
- `Headers/IServer.h` 和 Heaven 对应接口头增加独立 `IClientTls` 接口，保留原 `IServer`、`IGameClientProtocol` 布局。Heaven 的 IID 定义同步更新。
- `Bishop/Intercessor.cpp` 与 `GameServer/KSOServer.cpp` 在监听前启用 TLS，失败则停止该启动流程。
- 日志区分 `receive` 原始 TLS 片段、`tls_plain` 应用片段、`frame` 重组帧和 `request` 业务请求。握手完成记录版本及套件；失败和超时有独立记录。不注册 TLS 密钥导出日志。
- 每连接握手超时 15 秒，握手输入缓存上限 128 KiB，待发应用队列上限 1 MiB。TLS 记录通过现有有序写队列按 IOCP 缓冲容量拆分发送。
- 未增加 Gateway、代理或其他服务端进程，业务服务端实现仍为 C/C++，数据库仍为现有 SQL Server LocalDB。
- 未增加资源配置。没有修改 `Resources`、`.gitignore`、账号 `test001` 或其角色数据。

## 构建及本地身份

Windows 10 19045 的系统 TLS 无法提供本轮需要的 TLS 1.3，采用 OpenSSL 3.5.9 的 Win32 `/MT` 静态库，编入 Heaven，无需运行时 OpenSSL DLL。

`BuildOpenSsl.ps1` 与 `OpenSSL.md` 保留固定版本、源归档 SHA256、构建方式和来源。依赖源码、头文件及静态库均留在 `Test/Dependencies`；本轮实际编译工作在 `Test/Client20261030`。没有把第三方二进制或测试生成物加入 Git。

监听启动时在内存中生成本地 RSA 密钥及自签证书，不写系统信任或私钥文件。证书仅标识 localhost / 127.0.0.1。该方式用于当前本地客户端适配，公共服务器的可信身份管理不在本轮范围内。

## 真实客户端证书调查

后台 GUI IDA 附加用户指定 EXE，实际校验函数 `X509_verify_cert` 位于 `0x9ABD80`。读取校验上下文及 X509_STORE，确认其中仅有一个正式服证书对象，外部证书查找方法栈为空。证书的主题及颁发者均为 `OU=FSFee Game TLS,O=Seayoo,CN=fs.seayoo.com`，有效期 2024-10-15 至 2028-10-14；仅导出公开证书到 Test 以核对结构，未读取正式服私钥。

调试重启时在初始化栈上观察到该证书的 PEM 文本。软件断点调试期间发生一次虚拟化代码异常，不能据此声称普通启动也会崩溃；已停止该测试进程，并换用硬件断点。最后清理跟踪钩子、计时器及断点，解除调试附加。没有修改正式客户端二进制或 Windows 信任库。

现有客户端及 Resources 中未找到可供本地服务端使用的证书/私钥，也未确认客户端支持外部本地证书配置。单纯为服务端每次生成自签证书不足以适配。拟新增稳定的本地证书资源并实现独立客户端信任适配，具体范围保存在 `Test/Client20261030/待批准方案.md`。按 AGENTS.md 第 4 条，此类新资源在得到用户批准前不创建或部署；当前仍未修复真实客户端的登录前握手。
