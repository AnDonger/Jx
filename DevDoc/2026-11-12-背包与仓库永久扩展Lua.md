## Lua与C++分工

`Resources/script/背包仓库扩展.lua`负责费用表、逐行条件、菜单、双确认、余额检查、扣铜钱调用、开启调用、成功提示和日志。没有把费用或菜单放到C++，Lua不直接访问数据库。

C++新增五个通用接口：GetInventoryPurchase、GetBagRowState、ExtendBag、GetStoreBoxRentTime、RentStoreBox，参数／作用域／返回值／回滚边界已同步到 `DevDoc/当前Lua可用函数说明.md`。ExtendBag和RentStoreBox只修改权限，本身不扣费；费用由Lua先调用WasteCopperCash，扣费和权限在同一自动事务内提交，Lua错误完整恢复本次铜钱和权限。

协议层将原生请求转交系统Lua；回调仍使用现有79窗口token和B8/45反馈校验。必须同一地图、已进图、存活、未交易／切图／退出；仓库购买必须已取得使用许可并在对应箱子附近。重复、跳行、余额不足、过期反馈及非法参数不产生购买扣费。

## 本版协议与容器

| 方向／用途 | 格式／规则 |
| --- | --- |
| C2S购买背包行 | B8 05 00 0B 00 row，row=0～6 |
| S2C背包权限 | F8 05 00 18 01 mask，mask低7位按行累计 |
| C2S购买仓库页 | B2 index，index=0～5，对应第2～7页 |
| S2C单页权限 | 93 08 00 01 index DWORD(31536000) |
| S2C完整开箱 | 38字节，偏移6起六个DWORD权限，保留原未知字节和两个尾部固定1 |
| C2S确认／取消 | B8/45 MessagePack，确认0，原生日志取消255映射为-1，不调用购买回调 |
| S2C铜钱通知 | CC，Currency=1，Amount为本次实际扣除数 |
| 背包位置 | 第一页Place3、第二页Place19，每页5×7；第二页跨行物品必须覆盖行全部已购买 |
| 仓库位置 | 第一页Place4，第2～6页Place13～17，第7页Place21；每页6×8 |

仓库31536000是当前客户端识别的永久权限标记，本实现不递减，不作为UTC到期时间。回购仍使用Place12。所有权限、位置和物品尺寸均由服务端检查，不能向未购买的格子放物品。

客户端静态核对使用后台GUI IDA及本轮 `Test/InventoryExpansion20261111/inspection.i64`：93处理入口0x7B1E80，F8/18分支0x7B9253，行权限0x751CD0，物品位置映射0x748BF0／0x755430／0x755460。静态映射与正式服样本及实际TLS分别核对；静态分析不能证明界面已实测。

## 源码与存档

- `GameDataDef.h`：新增扩展房间、位置映射、权限数据和物品容量，旧房间编号保持。
- `KItemList.cpp/.h`：按权限检查两页背包／七页仓库；支持拿起、放下、跨页、堆叠、拆分、自动寻位、拾取、铜钱购买双矩阵规划与商店回购移动。
- `KBuySell.cpp`：第二页买卖、回购和背包装备修理入口。
- `KPlayer.cpp/.h`：系统Lua购买上下文、权限同步、开箱包、第二页物品使用、回城／技能书及原地复活铜钱范围。
- `KProtocolProcess.cpp/.h`、`CoreServerShell.cpp`：B2、B8/0B、取消255及扩展仓库操作校验。
- `ScriptFuns.cpp`：五个接口、两页材料／铜钱查扣、第二页发奖、扩展权限事务快照及提交同步。
- `KPlayerDBFuns.cpp`：SPG1 v5在变身数据之后追加28字节权限，兼容v1～4；严格校验连续行位和六个永久标记。加载权限先于物品加载，登录权限包在技能扩展读取完成后、物品包之前发送。保存物品记录增加缓冲区边界检查，标准TRoleData和旧物品扩展不改布局。
