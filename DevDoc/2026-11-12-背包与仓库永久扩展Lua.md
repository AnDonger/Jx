## Lua与C++分工

`Resources/script/背包仓库扩展.lua`负责费用表、逐行条件、菜单、双确认、余额检查、扣铜钱调用、开启调用、成功提示和日志。没有把费用或菜单放到C++，Lua不直接访问数据库。

C++新增五个通用接口：GetInventoryPurchase、GetBagRowState、ExtendBag、GetStoreBoxRentTime、RentStoreBox，参数／作用域／返回值／回滚边界已同步到 `DevDoc/当前Lua可用函数说明.md`。ExtendBag和RentStoreBox只修改权限，本身不扣费；费用由Lua先调用WasteCopperCash，扣费和权限在同一自动事务内提交，Lua错误完整恢复本次铜钱和权限。

协议层将原生请求转交系统Lua；回调仍使用现有79窗口token和B8/45反馈校验。必须同一地图、已进图、存活、未交易／切图／退出；仓库购买必须已取得使用许可并在对应箱子附近。重复、跳行、余额不足、过期反馈及非法参数不产生购买扣费。

## 本版协议与容器

| 方向／用途 | 格式／规则 |
| --- | --- |
| C2S购买背包行 | B8 05 00 0B 00 row，row=0～6 |
| S2C背包权限 | F8 05 00 18 01 mask，mask低7位按行累计 |
| C2S购买仓库页 | B2 index，index=0～5，对应第2～7页 |
| S2C单页权限 | 93 08 00 01 index DWORD(31536000) |
| S2C完整开箱 | 38字节，偏移6起六个DWORD权限，保留原未知字节和两个尾部固定1 |
| C2S确认／取消 | B8/45 MessagePack，确认0，原生日志取消255映射为-1，不调用购买回调 |
| S2C铜钱通知 | CC，Currency=1，Amount为本次实际扣除数 |
| 背包位置 | 第一页Place3、第二页Place19，每页5×7；第二页跨行物品必须覆盖行全部已购买 |

仓库31536000是当前客户端识别的永久权限标记，本实现不递减，不作为UTC到期时间。回购仍使用Place12。所有权限、位置和物品尺寸均由服务端检查，不能向未购买的格子放物品。

客户端静态核对使用后台GUI IDA及本轮 `Test/InventoryExpansion20261111/inspection.i64`：93处理入口0x7B1E80，F8/18分支0x7B9253，行权限0x751CD0，物品位置映射0x748BF0／0x755430／0x755460。静态映射与正式服样本及实际TLS分别核对；静态分析不能证明界面已实测。

## 2026-11-16：背包第三页及更多页支持范围核对

日期：2026-11-16。

### 结论

当前服务端实现和本项目基准客户端的原生背包流程均只支持两页：第一页 Place3，第二页 Place19。未发现可通过 Lua、资源页签或权限包直接开启的第三页背包。要增加第三页或更多页，需要修改客户端程序并配套扩展服务端，不能仅调整服务端购买脚本。

这是当前源码及客户端静态代码的结论。本轮没有登录角色、修改数据库、发送测试包或进行客户端 UI 动态验收，也没有修改游戏源码、客户端或生产资源。

#### 页签和切页有明确上限

`0x5E24C0` 从资源读取 `BtnPage_%d`，控件步长 448，循环总长度 896，实际只绑定 `BtnPage_0`、`BtnPage_1`；同时只绑定七个 `DisableImg_%d` 行遮罩。

`0x5E07D0` 切页入口首先检查 `a2 < 2`。页号 0 对应第一页，页号 1 对应第二页；传入页号 2 不进入切页处理。内部更新页签的循环也明确限制为两次。因此，给资源文件增加 `BtnPage_2` 并不能让当前客户端使用第三页。

#### 扩展页物品枚举同样拒绝第三页

`0x6CF7D0` 的 CoreShell 数据查询 `case 166`：

```cpp
if (a5 != 0)
    return 0;
// 其余分支仅统计或输出 Place == 19 的物品
```

`0x5E07D0` 请求扩展页物品时传入当前页号减一。因此第二页传入 0 可枚举，假设第三页传入 1，会被此接口直接拒绝。这是独立于页签数量的底层限制。

#### 权限位容器通用，但背包权限检查只允许一个扩展页

`0x751CD0` 的实际汇编先判断扩展页索引为 0，再判断行号不大于 6，否则返回 0：

```asm
test edx, edx
jnz  loc_751D02
cmp  [ebp+arg_4], 6
ja   loc_751D02
```

后面的位索引运算保留 `7 * 扩展页索引 + 行号` 的通用形式，调用 `0x7404F0` 读取位。该形式说明代码有通用化的结构，但前面的明确限制使扩展页索引 1 及以上不可用，不能据此认定已支持第三页。

F8/18 入口 `0x7B9253` 读取包偏移 4 的字节，连同偏移 5 起的数据调用 `0x751C90`，再由 `0x740A60` 按长度复制权限位数据。当前 `F8 05 00 18 01 mask` 中的 `01` 在此路径作为数据字节数使用，不能把它当作页数或页号，改成 `02` 也不会绕过上述限制。底层位容器能接收较长数据，不等于背包业务支持更多页。

#### 物品接收和自动寻位没有隐藏第三页

- 物品接收 `0x748BF0`：普通背包使用 Place3，扩展背包单独接受 Place19 并调用 `0x751CD0(0, row)`；其他未匹配的 Place 不能进入这个扩展背包分支。
- 自动寻位 `0x70CF20`：先找第一页，再搜索一个扩展背包；其扩展搜索上限只有一次，成功输出 Place19，最终还检查扩展索引小于 1。
- 背包装备操作 `0x74A410`：入口只接受该函数内部使用的第一页值 0 或第二页值 19。此处内部 0 不能误读成协议 Place0。
- 界面物品操作 `0x5E2830`：当前页号 0 映射 UI 容器 5，页号 1 映射 UI 容器 27。UI 容器编号与协议 Place 是不同枚举，不能把 UI 容器 27 当成第三页 Place。

#### 额外容器号不等于额外背包页

`0x751D10`、`0x755430`、`0x755460` 将 Place4、13～17、21～23 归入仓库相关映射，其中 Place21～23 映射到仓库页序号 7～9。特别是 Place22、23，不能当作背包第三、第四页使用。

这里确认的是仓库分类和页号映射存在；没有据此宣称仓库第八、九页的购买、界面和存档已经完整可用。服务端当前只实现七页仓库。

### 后续扩页的实际边界

若决定开发第三页，需要先制定客户端新页的 Place、矩阵、页签、物品枚举与权限格式，修改客户端上述限制和相关操作路径；服务端同步增加容器、权限、Lua 页参数、入包与购买规划、事务快照、存档兼容和容量预算。只去掉一个条件或放宽 `BagRows` 校验不足以形成完整功能。

本轮完成的是静态能力核对。没有进行扩页补丁试验或真实客户端第三页收发、拖放、使用及重登测试；其他客户端版本也不在本结论范围内。
