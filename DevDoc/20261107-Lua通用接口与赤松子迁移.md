## 本轮新增的通用接口

### ReadTabFile(path)

- 通过原 `KTabFile` 和资源加载链读取表，成功返回二维字符串数组，行列从1开始；保留首行表头、空格和行顺序，空单元格为 `""`。
- 失败返回nil，不创建替代资源。路径以反斜杠开头，禁止盘符和父目录跳转，设置行列及单元格长度上限，拒绝截断内容。
- Lua负责业务字段解析和缓存。示例：`local rows = ReadTabFile("\\settings\\item\\001\\装备合成规则表.txt")`。

### GetGameVersion()

- 返回服务端当前资源版本，脚本按版本选择原表，避免另写一份版本配置。

### GetSelectedItems()

- 只在当前窗口请求回调有效，返回经过服务端验证的提交物品数组。字段为 `Genre`、`Detail`、`Particular`、`Level`、`Count`、`Bound`、`BindingMode`。
- 数组下标即本次请求的槽号，不能将客户端提供的任意ID作为服务端物品索引。重复位置、非自身背包、错误版本等在进入脚本前拒绝。
- 请求结束或完成后返回nil。不要跨请求保存这个数组作为可操作物品凭据。

### DelSelectedItem(slot, count)

- 按本次请求1起始的槽号精确扣数量，返回1或0；再次核实物品ID、剩余数量和所有权。
- 只扣当前提交的那一叠，不会从其他同名物品补扣。事务内失败会终止脚本并使整次操作回滚。

### CompleteItemOperation(result)

- result=1表示本次操作成功；result=0表示已经完成、但概率结果为失败，材料和费用仍按脚本规则提交。
- 只能在当前请求事务内调用一次。未调用、脚本报错或事务失败，整次操作回滚。即使先调用此函数，后续脚本报错也不能留下半次交易。
- 该函数只登记脚本结果，最终提交与协议响应由通用入口处理；不应在客户端自行执行。

## 扩展已有接口

原六参数调用及原第七参数0保持兼容：

```lua
AddNormalItem(genre, detail, particular, level, series, luck)
```

第七参数可使用可选表：

```lua
AddNormalItem(3, 173, 0, 0, 0, 0,
    {Count=1, Bound=0, BindingMode=0})
```

- Count默认为1，实际受原物品模板堆叠上限约束；装备只能为1。Bound默认为0，BindingMode默认为0，绑定模式使用真实来源数据。
- 返回值保持原来的成功标识和属性说明，不改成物品索引。物品生成、耐久、可见背包寻位、叠加和即时同步均复用原流程。
- `PutMessage()` 与 `Msg2Player()` 在NPC物品事务中延迟到最外层提交后发送；回滚时丢弃，以免出现扣钱已恢复但仍提示扣费成功的情况。事务外保留原有发送行为。
- 现有NPC材料事务仍只快照随身背包、快捷栏、鼠标物品、现金和任务等已有范围，不宣称已支持任意装备栏、仓库、婚姻或帮会状态的回滚。其他普通对话回调的自动事务范围尚未整体扩展；本次窗口请求通过通用入口显式建立事务，不依赖地图52的旧特例。

## 赤松子Lua实现

- `dz_new()` / `dz()` 分别打开新旧窗口并指定 `OnCompound` 回调，继续使用原窗口协议。
- `compound_load_rules()` 按当前版本读取原《装备合成规则表.txt》《装备合成金钱需求.txt》，按同一行及规则ID核对费用，缓存本批支持的177条材料/脚本道具配方。
- 仍拒绝品质/等级掩码装备规则、尚未适配的生活技能及职业限制，不用普通材料逻辑替代它们。
- `compound_match()` 在Lua匹配提交的各叠材料及精确扣取量；多余物品不忽略，同一叠不能重复计算。
- `OnCompound()` 在Lua检查原玲珑锁任务464、现金和配方，按原成功率抽取结果，调用 `DelSelectedItem`、`Pay`、`AddNormalItem` 完成消耗与奖励；精石100%来自原配方，没有写死精石ID或20万费用。
- 绑定来源与绑定模式由Lua读取提交物品并传给发奖接口。扣费提示文本及业务日志也在Lua。
- 条件不足、满包、发奖失败或脚本异常均由原事务恢复；概率失败则按原配方消耗，不发成品。
