## 修改

1. `Headers/KProtocol.h`：增加11字节单技能冷却包、5字节列表头及6字节列表记录，保留未知字段并增加尺寸断言。
2. `KSkillList.h/.cpp`：通用冷却通知及完整列表同步。施放接受时先在服务端预留冷却，效果帧到达后发送一次F8/2D；冷却内拒绝的请求不重复扣蓝、不重新启动计时；零固定冷却不发送虚假计时。超过WORD范围的冷却使用绝对帧列表，避免截断。
3. `KNpc.cpp`：接受施放时的预留不重复通知，沿用效果帧原有计时更新流程。
4. `KPlayer.cpp`：技能快照0x45之后同步F8/4B，恢复客户端当前技能冷却。
5. `KPlayerDBFuns.cpp`：SPG1技能扩展升为版本3，原12字节技能记录后增加低／高DWORD，保存自1601年起的毫秒到期时间。宠物及BUFF区仍按原格式保存；加载时兼容版本1、2，版本3按离线经过时间扣减，并换算到当前地图世界帧。到期清零，不保存旧进程的世界帧。新增时间跨度及溢出校验，恢复失败时回滚本次冷却赋值，再提交其他技能和宠物状态。

只修改上述6个源码文件，没有新增资源配置、Lua接口或数据库表。C++保持GBK、LF；既有暂存内容保持原样，没有替用户暂存或提交本轮更改。版本3存档应使用支持该版本的服务端读取，旧版本服务端只识别1／2。

## 追加：反复施放偶发漏显示冷却

用户实测确认上轮重登剩余冷却、到期后再次施放正常；但多次施放偶发不显示冷却，客户端仍可重复播放施法。本段记录后续修正，取代前文“预留不通知、拒绝不通知”的处理。

后台 GUI IDA 继续使用相同客户端和已有数据库，四个相关函数的完整机器码与当前 EXE 文件逐字节一致，结果见 `Test/SkillCooldownRetry20261109/client-cooldown-writes.json`。本轮自建 GUI IDA 分析结束后自行退出，未操作用户其他 IDA。

静态已确认：

- `0x783F60` 处理 F8/2D 时计算第二个参数，但调用的 `0x714CC0` 并未采用这个参数。后者将技能槽的 `+40`（本地预计算值）复制到 `+36`（当前冷却），再触发 UI 事件150。不能把“收到 F8/2D”当作“服务端到期时间已写入客户端”的证明。
- `0x714D60` 的调用包含客户端自身动作效果帧 `0x783AA0`，本地预计算值的更新与动作时序有关。
- F8/4B 路径 `0x7C4220 → 0x783E90` 直接将服务器传入的绝对结束帧写入 `+36`，并触发同一 UI 事件；处理器按条更新，不要求必须包含全部技能。
- 由此判断此前偶发漏显示与本地预计算／通知时序有关。尚未动态捕获用户漏显示瞬间的两个槽值，因而不把某一条具体时序当作已动态复现的根因。

本轮仅继续修改 `KNpc.cpp`、`KSkillList.cpp`、`KSkillList.h`：

1. `SyncPlayerSkillCooldowns(int nSkillID = 0)` 支持同步指定技能；0仍表示登录时同步完整列表。指定未知技能不发包，不影响其他技能。
2. 接受施放、预留服务器冷却时，立即同步该技能的 F8/4B，使随后动作中断时仍能显示已预留的冷却。
3. 效果帧保留一次 F8/2D，紧接着发送该技能的 F8/4B，用真实到期帧校正本地预计算值。
4. 命令处理或直接施放入口因冷却拒绝请求时，补发该技能的真实到期帧。保持原到期时间，不重扣内力、不重复产生技能效果，也不重新发送施放成功通知。
5. 只发送当次技能记录，避免顺带更新其他技能的冷却。客户端、资源、Lua和存档格式均未改动。
