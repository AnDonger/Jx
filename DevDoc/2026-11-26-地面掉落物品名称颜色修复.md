# 地面掉落物品名称颜色修复

日期：2026-11-26。状态：已编译、回归并部署；实际客户端画面待用户确认。

## 问题与证据

用户反馈背包中的物品字体颜色正确，掉到地上后却全部显示白色。

正式服记录：`F:\mxd\VsFsbServer\tests\build\x64\Debug\DataLog\20261119_233131_215.log`。
提取已解密 `Plain=`，跳过外层2字节长度，按对象ID及名称去重得到57个地面对象：白色47个、蓝色7个、黄色3个。本份记录没有绿色样本，不能将其写成正式服绿色封包已验证。

- `0x4F GAME_OBJECT_ADD_SYNC` 的 `Color` 是从协议字节开始计数的偏移33，宽1字节；名称从偏移39开始。
- 正式服蓝色样本包括巨斗披风、天权令、云中冠、巨斗腰带、灭焰剑、巨斗盔；黄色样本为混天凌、琉璃瓶、火龙镖。
- 同名装备也存在白色样本，不能按物品名字指定颜色。
- 当前原资源 `settings/obj/objnamecolor.ini`：0白、1蓝、2绿、3黄、4紫。

后台 GUI IDA 对项目 `Release/Client/Game.unpacked.exe` 的静态核对：SHA256 `2547d4c11daf0c3f7ca19dfa0800295d95474cd0bfa5574dce6ca67bef8ed7ce`；`0x738460` 是品质颜色判定，`0x73DDA0` 的物品名称着色亦可交叉核对。未修改客户端。

## 根因与修改

怪物随机掉落、NPC/Lua掉落、玩家丢弃等调用方把 `KObjItemInfo.m_nColorID` 填成0或零初始化。公共创建流程直接保存这个值，并写进首次0x4F广播；重新进入视野时，`KObj::SyncAdd` 又发送已保存的0，因此一直显示白色。

修改源码：

- `Sources/Core/Src/KItem.h`、`KItem.cpp`：补齐通用 `GetQualityLabel()`，对照当前客户端规则读取对应版本装备模板，判定实际品质。
- `Sources/Core/Src/KObjSet.cpp`：有真实物品时统一从物品品质取得颜色，同时保存给首次广播及重新入场同步使用；无物品的金钱对象保留原有颜色。增加物品索引/存活校验。

常规装备规则：

| 原模板 m_nSeries | 颜色 |
| --- | --- |
| 0，第一随机属性槽为空 | 白色0 |
| 0，第一随机属性槽非空 | 蓝色1 |
| 1～999 | 绿色2 |
| 1000 | 黄色3 |
| 2000 | 紫色4 |
| 其他 | 白色0 |

非装备返回0。客户端详细类别15另有独立编码：1000蓝、2000黄、3000紫，其余白；该分支按客户端保留，当前服务端模板查找尚不支持此类别，本轮没有新增该类别的资源或加载能力。

这里必须读取原模板的 `m_nSeries`；物品实例 `GetSeries()` 已被装备生成流程写成角色五行/职业值，不能拿来判断套装或品质。模板标记5000也不能臆测成黄金，本轮遵循客户端回退白色的行为。

本轮未修改掉落概率、属性生成、物品数量、背包配色、资源和客户端。
