## 协议

以下长度不含最外层 TCP 的 WORD 长度。外层加解密与登录握手沿用已验证的原生网络模块。

| 功能 | 编号 | 当前布局 |
| --- | --- | --- |
| 创建 | `0x45` | 10 字节 TProcessData 头，后接性别 BYTE、职业 BYTE、出生地图 WORD、头像 BYTE、GBK 名字及 NUL |
| 删除 | `0x3A` | 129 字节：编号、账号 32、密码摘要缓冲 64、角色名 32 |
| 选择已有角色 | `0x6C` | 33 字节：编号、角色名 32 |
| 创建/删除结果 | `0x97` | 34 字节：编号、名字或失败原因 32、成功标志 BYTE |
| 获取角色列表 | `0x37` | 11 字节头，后接完整 LZO 流，每个角色 82 字节 |

82 字节角色记录：名字 0、性别 32、职业 33、等级 34、头像 35、经验 DWORD 36、unknown_1 BYTE 40、上次退出时间 DWORD 41、IP DWORD 45、地图 DWORD 49、unknown_2[29] 53。未知区当前固定零；退出时间和 IP 尚未接入统计，当前也为零。地图是 DWORD，以客户端实际读取为准。

创建成功后继续原有的数据库读取和游戏服转交流程；客户端会自动等待进图地址。删除成功后客户端自行移除列表项，重登再从数据库读取，不额外向该客户端状态发送列表。

## 源码和资源

- Bishop `GamePlayer.cpp/.h`：解析当前创建和删除布局，维护已认证账号的角色名单，检查角色归属，验证删除密码，提交成功后才返回创建成功，选择角色时重新从数据库读取。
- Bishop `LoginDef.h`：当前客户端布局和长度检查。
- `Headers\S3DBInterface.h` 与现有相同副本 `lib\S3DBInterface.h`：增加独立的当前列表记录与内部账号归属请求结构，保持旧 TRoleData 游戏存档布局。两个现有副本均需同步，因为实际工程的 include 搜索顺序先到 lib。
- Bishop `PlayerCreator.cpp/.h`：优先加载 `Resources\settings\npc\player\newplayerini00.ini` 至 05；出生地图使用 `NativePlaceList.ini`，出生区域和世界坐标使用 `RevivePos.ini`。职业 0/1/2 与性别 0/1 对应六个模板。没有创建自编出生表。
- Goddess `ClientNode.cpp`：创建、读取、保存、删除入口校验实际封包长度；内部当前请求携带已认证账号，再次核对角色归属。
- Goddess `IDBRoleServer.cpp/.h`：在原数据库模块使用 ODBC 访问 SQL Server，角色名与账号参数使用 Unicode 参数绑定；角色名按二进制排序规则判重。创建在事务中检查同名与每账号最多三个角色。头像单独存列，原有游戏保存不会覆盖头像。
- Goddess `DBTable.cpp/.h`：兼容读取旧库时注册调用方分配函数，避免 Debug 数据库库分配的 DBT 缓冲由另一运行库释放；遍历主库时显式使用 primary_db，关闭有效游标并初始化游标指针。
- Bishop `GameServer.cpp`：初始化进图通知结构，避免未使用的名字缓冲发送栈残留。
- GameServer `KSOServer.cpp`：优先使用已有 `ServerCfg.ini` 的 `GameServer.Ip` 对外通告，缺省才保留网卡自动识别结果。本机现配置为 `127.0.0.1`，避免返回虚拟网卡的 `169.254.29.13`。
- Goddess `Goddess.cpp`：后台模式收到关闭请求可正常释放服务和数据库，不弹交互确认框；界面不再将 SQL 角色库误报为 Berkeley 备份线程正在运行。

修改保持原 GBK 编码、原文件换行与项目展开格式。没有运行 clang-format。

## 数据库和旧记录

沿用已有 `Release\Server\DataBase.ini` 的 `[role]`，连接同一 SQL Server 实例、数据库 `JxRole`。原账号段保持不变。

`dbo.Role_Info` 保存角色名、账号、完整原生 RoleData 和头像。`RoleStorageMigration` 记录一次性旧库迁移完成状态，避免删除后在重启时重新导入旧记录。Goddess 会在目标数据库中初始化这些表及角色账号索引。

旧 `database\roledb` 实际还有两条记录，不能通过文件大小判断为空：343 字节记录的角色名带控制字节，3989 字节旧示例记录不符合当前 TRoleData 布局。它们完整保存到 `dbo.RoleLegacyArchive`，均为 Imported=0，没有加入当前可用角色列表。原文件另有部署前备份。开发过程第一轮迁移曾临时导入那条控制字符名字记录；完整归档后仅移除了与该归档内容完全相同的临时导入行。

SQL 备份使用数据库原生 COPY_ONLY BACKUP，不能在实例运行中直接复制 MDF/LDF。旧 Berkeley 自动备份不是 SQL Server 备份，本次没有实现定时 SQL 备份任务。
