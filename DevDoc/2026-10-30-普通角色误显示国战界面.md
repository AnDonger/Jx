# 普通角色误显示国战信息和备战进度条

## 问题

普通场景进图后，顶部出现参战人数、建筑、战车、硫磺、青铜、金钱、重生水晶信息，下方同时出现空的备战进度条。用户截图为 `QQ20261030-015815.png`。

## 客户端静态证据

基准是 `Release/Client/Game.unpacked.exe`，SHA256 为 `7179134950a58df1271e36c3f1ddcd2f12c4e0c054032175166f59faf090e200`。复用后台 GUI IDA，未修改客户端或资源。分析过程沿用 reverse-engineer-anything 技能，证据保存于 `Test/WarHud`。

1. 顶部窗口为 `KUiWarInfoHeadBar`，读取当前 UI 目录的 `国战信息.ini`；其中上限与截图的 100、121、21、200 一致。下方窗口读取 `备战进度条.ini`。详见 `Resource-findings.md`、`hud-resource-identity.json` 和 `lower-bar-functions.json`。
2. 客户端 `0x5866D2` 附近通过 CoreShell 查询 63，非零时显示两者，零时关闭两者。详见 `headbar-callsite.json`。
3. CoreShell `0x698980` 的查询 63 分支位于 `0x6997E5`，返回本机 NPC 的 `+0x1970`（十进制 6512）字段。详见 `query-entry.json`、`query-case.json`。
4. 周期同步 `0x4D` 的处理器为 `0x7670F0`。消息 `+1` 经中间结构传给 `0x763C20`：非零时将 NPC `+6512` 写成 1；零时清空从该处开始的 48 字节国战数据。状态改变时还发出 Core 事件 265。详见 `npc-state.json`，以及 `Test/PlayerInteraction/ida-0x763c20.txt`。
5. 初始同步 `0x4C` 的处理器为 `0x765D40`。它读取名字字符串终止符后的一个字节作为国战状态；当前服务端该字节已经为零。固定头 `+7` 仍传给 `0x73FB00` 处理菜单状态，不是这里的国战开关，因此没有修改该字段。详见 `npc-state.json`。初始字段位置以实际反编译为准，不能将 `+7` 误判为国战状态。

以上为静态调用链证据，不代表已经观察到修复后客户端画面。

## 服务端修改

- `Headers/KProtocol.h`：将当前 29 字节 `GAME_NPC_NORMAL_SYNC` 的 `State` 明确命名为 `WarState`，字段宽度、位置和协议长度不变。旧版 `NPC_NORMAL_SYNC` 保持原定义。
- `Sources/Core/Src/KNpc.cpp`：`KNpc::NormalSync()` 不再固定发送 1，当前未接入国战的普通场景发送 `WarState = 0`，并补充字段用途说明。
- 初始 `0x4C` 的零状态尾部保持原逻辑。没有通过删改 UI 资源来隐藏界面，没有新建替代配置。

参考项目中旧版 `NPC_NORMAL_SYNC.State` 用于冻结、中毒等状态位，与当前客户端本字段的语义不同；不能因字段旧名相同而套用旧版含义。参考范围包括 `Jx1-Thiendieuvs2022`、`jx1-vs2022`、`fsb2_Source_code` 的现有 NPC 同步代码，并与当前客户端处理器交叉核对。

## 构建与部署

仅重新构建现有 Core 模块，输出 `Test/MapList/Build/Core/Coreserver.dll`。部署脚本位于 `Test/WarHud/Deploy.ps1`，仅替换该 DLL 及对应导入库，没有复制其他旧构建的 EXE。部署前检查客户端连接和 SQL 在线状态，备份现有二进制与 SQL 数据库，再重启原服务。

部署时间、发布文件哈希和备份位置见 `Test/WarHud/deployment.json`。源码改动前副本见 `Test/WarHud/BeforeSourceChange`。本轮保持源码原有 GBK 编码和换行，不进行批量格式化。

## 验证

构建通过，`git diff --check` 通过。启动健康验证检查本项目端口、SQL Server 账号、原生登录握手及地图注册。

真实加密 TCP 测试使用独立账号及角色，不操作用户已有角色。测试脚本为 `Test/WarHud/Verify-WarHud.py`，核对初始 `0x4C` 国战状态、周期 `0x4D` 国战状态，并覆盖移动、四次武器拿放和重登位置保持。结果见 `Test/WarHud/verification.json`，封包见 `capture-new-role.json`、`capture-reload.json`。

实际结果：两次进图的初始国战状态均为零，首次进图 121 条、重登后 27 条周期同步的国战状态全部为零；四次物品交互和移动通过，重登整数世界坐标保持一致。发布 DLL 的 SHA256 与本轮构建一致。独立测试角色已通过原协议删除，测试账号在正常断线释放后清理。前后数据库快照核对，用户已有 3 个角色的记录（含 RoleData）完全一致。

客户端画面仍需用户重新登录，确认顶部国战信息和下方备战进度条同时消失。TCP 验证不替代该项画面实测。
