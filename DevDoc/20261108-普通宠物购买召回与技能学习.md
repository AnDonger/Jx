## 本轮实现

1. 普通宠物以角色附属状态保存，不占地图固定NPC或刷怪配置。保存类型、名字、亲密度、颜色、召出状态及学习权限。
2. 右键真实背包脚本道具时，从物品原模板加载原Lua。确认回调继续沿用当前B8对白令牌和已有函数检查；扣道具、发道具、现金及宠物变更进入通用事务。
3. 脚本执行失败时恢复本次相关背包物品、唯一ID、位置、数量、现金、任务和宠物状态；宠物同步延迟到事务提交，避免失败后客户端出现未落档的宠物。
4. 道具事务入口额外限制可调用接口，只允许已覆盖快照的变更和查询／纯计算／对白等接口。地图、技能、Buff及外部IO等副作用未接入此入口，不宣称支持任意脚本完整回滚。
5. 新增13个通用Lua注册名：SaleEx、GetPetType、GetPetHonor、GetPetColor、GetPetName、IsPetReleased、GenPet、DelPet、SetPetType、SetPetHonor、ReleasePet、GetPetFuncAuthority、SetPetFuncAuthority。参数、返回值、示例和限制已写入当前Lua函数表。
6. `SaleEx` 复用原商店和原模板“铜钱价格”，使用现有物品货币原子购买能力。余额不足或背包满时不扣铜钱；铜钱商店不能套用现金出售／回购。
7. 寿星学习确认时再次检查召出状态、重复学习和前置权限，防止重复扣费；修正原脚本召役铃的level为当前原模板实际存在的1。
8. 15份已有认主脚本修正召役铃模板level并增加确认时已有宠物校验，不再删除已有宠物后覆盖认主；各脚本GenPet的初始亲密度保持原值。
9. 角色技能扩展SPG1从版本1扩为版本2，末尾新增48字节普通宠物记录；兼容版本1和无扩展旧档，不改变基础角色／物品ABI，不新增SQL表。Lua不接触数据库。
10. 已有资源管理后台 `F:\mxd\FsbFastApi\app\jx_codec.py` 同步兼容版本2；编辑角色字段或背包时原样保留宠物字节。这是已有管理工具的存档兼容，未增加Python服务端。该后台当前进程未开启自动重载，重新启动后台后才会使用新解析器。

## 当前协议结论

当前普通宠物使用0xDB变长协议。以下偏移均以协议首字节为0，不含外层2字节传输长度。

| 偏移 | 内容 |
| --- | --- |
| 0 | BYTE 0xDB |
| 1 | WORD 协议总长减1 |
| 3 | BYTE 子类型，0初始化、1普通同步 |
| 4 | DWORD 主人网络ID |
| 8 | BYTE 类型左移1加召出位，绿飞飞召出9／收回8 |
| 9 | BYTE 亲密度 |
| 10 | BYTE 原始颜色 |
| 11 | WORD 功能权限；DB/0携带真实值，DB/1为0 |
| 13 | WORD 功能启用位；DB/0携带真实值，DB/1为0 |
| 15 | DWORD 拾取过滤 |
| 19 | DWORD 清理过滤与阈值 |
| 23 | 初始化包为不含NUL的GBK名字；普通包为1字节标志，当前保留0 |

- 后台GUI IDA数据库及输出位于 `Test/Pet20261107/client.i64`、`ida-pet-*.json`。确认DB处理入口0x7BFBA0、普通宠物索引NPC+0x2264、类型+0x2268、亲密度+0xA3F9。
- 0x6F8970按0～4的位查询Player+0x200，与原Lua五权限及用户补充的0x0B一致。
- 实录DB/0权限为11，周期DB/1为0；客户端两个分支均写Player+0x200。首批实现曾选择两种包都发真实权限；11月8日新实录已纠正：周期DB/1的两个WORD保持0，技能按钮由DB/13 kind4独立同步。
- 首批将DB/13误判为仅限仙兽，已由11月8日两份实录纠正：DB/13 kind4用于普通宠物的已学、启用状态。6EEB50返回容器节点指针，实际NPC在节点后16字节，节点+2274对应NPC+2264，不能仅以偏移不同判为仙兽。
- 其余未知字节保持原记录0；已确认的功能启用位与DB/13同步，其实际自动执行效果单独适配。
