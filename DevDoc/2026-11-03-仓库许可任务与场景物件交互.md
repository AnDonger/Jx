# 仓库许可任务与场景物件交互

日期：2026-11-03。客户端基准为 `Release/Client/Game.unpacked.20261030.exe`。

## 本轮范围

接通崇城大营、玉虚宫、蚩尤墓的“使用仓库”许可任务，以及完成后的固定储物箱开窗、物品存取、拆分合并、金钱存取和角色存档。通用部分复用原 Lua 脚本引擎、NPC 对话、任务变量及 SQL Server 角色二进制存档；没有新增服务端进程或 Python 服务。

本轮不代表所有原脚本任务已经可用。“六道轮回”的完整奖励逻辑、正式服新增“物品打包”等功能尚未实现；不修改原脚本来伪造已经接通的菜单。

## 位置与资源依据

正式服五份日志见 `Test/WarehouseTask/capture-summary.json`，对应用户本轮的记录一至记录四。三城捕获的 22 个固定 NPC 中，15 个站位与现有资源精确一致，7 个不同或缺失。有效资源、资源归档和参考服务端的限定检索没有找到与差异站位一致的原始放置记录，因此没有移动这些 NPC，包括三个仓库管理员。

用户批准的 7 个箱子集中在 `Resources/ServerConfig/FixedObjects.ini`：崇城 3 个、玉虚 2 个、蚩尤 2 个，使用捕获的 MPS 整数位置和原模板 2。文件内部记录来源、字段、启停、使用方法和重启生效方法；其他地图没有直接放置证据，不按经验推造箱子。

从原 PAK 条目恢复三城各自的 `仓库管理员.lua` 和 `储物箱.lua`，按原名、原字节保存到 `Resources/script`，6/6 原始字节 SHA256 核对见 `Test/WarehouseTask/warehouse-script-restoration.json`。恢复过程及站位检索另见本日的两份专项开发记录。

## 服务端实现

- `KSubWorld.cpp`：对未配置脚本的固定 NPC，尝试读取原地图目录下与 NPC 同名的实际脚本；只绑定确实存在且能编译的资源。显式脚本优先。箱子在原区域物件之后加载。
- `KObjSet.cpp/.h`：读取批准的固定物件配置；整批验证、精确坐标去重、失败回滚。不存在配置时不影响原地图加载。
- `KObj.cpp`：物件脚本按原资源路径按需编译。复用 `SyncAdd` 的 4F 场景同步。
- `KSubWorld.cpp/.h`：登录加入地图时同步周边九个区域的现有物件；跨区域只补发新进入视野的区域。切图后通过同一路径同步目的地物件。实际连接测试首先发现了原有代码缺少此同步入口，仅检查服务端内存不能发现这个遗漏。
- `ScriptFuns.cpp`：接通原 `SayTask`、`MsgBox`、`HaveNormalItem`、`DelNormalItem`、`TaskNote` 与 `OpenBox`。菜单按原 `show` 条件过滤；材料只计普通背包，按实际堆叠数累计，扣除后复用现有物品数量和删除同步。
- `KPlayer.cpp/.h`：保存并校验 NPC 对话来源、地图、距离和一次性反馈令牌；物件脚本具有临时对象上下文。仓库访问限定为本次点击的同图、近距离箱子，切图或释放角色时撤销。
- `KProtocolProcess.cpp/.h`、`CoreServerShell.cpp`、`Headers/KProtocol.h`：接通 9 字节 76 NPC 点击、9 字节 7C 物件点击、38 字节 93 开仓响应。仓库物品移动、拆分与金钱操作校验访问权限，拒绝物品操作仍返回 99 释放鼠标操作锁。
- `KPlayerTask.cpp/.h`、`KPlayerDBFuns.cpp`：任务栏按原 `settings/taskinfo.tbl` 同步，活动任务记录随角色保存、重登恢复。扩展放在标准任务变量与物品记录之间，包含 magic、版本、数量和边界检查，不修改数据库表结构，不占用未知任务变量。损坏任务扩展禁止继续加载和保存。

实际 TLS 重登测试还发现，原有连续加载游标只跳过标准任务变量，没有跳过新增的可选日志区。已在任务加载完成（包括标准变量数量为零的情况）时显式推进到 `dwItemOffset`，并加入任务阶段连续进入物品阶段的回归；不能只分别验证两个阶段。
- `KBasPropTbl.CPP/.h`、`KItemGenerator.CPP/.h`、`KItemSet.cpp`、`KItem.cpp`、`KPlayerDBFuns.cpp`：普通材料接回原属性表、生成器和存档读取。优先新 `material.txt`，旧表只作缺失时兼容；火羽、玉骨、碎甲使用原 tuple 和资源堆叠上限 200。

`network-test.log` 和 `network-verification.json`：三城均通过 TLS 1.3 登录、场景箱子同步、接取任务、退出重登恢复任务、交付材料、任务栏结束通知、开箱、背包与仓库往返存取、再次重登检查材料及许可。每个角色交付前材料为 7，扣除后为 2；崇城收到 3 个箱子，玉虚和蚩尤各 2 个。9 次登录、9 次游戏连接均为 TLS 1.3。

`storage-evidence.log`：进一步按已保存的三城实际响应核对，扣材料的 AD 数量依次为 6、5、4、3、2；四次存取均收到对应的 78 移动响应、AD 数量同步和 99 解锁，避免仅凭收到解锁包就认定存取成功。实际数量更新使用 AD（11 字节），不要求服务端额外发送 75。
